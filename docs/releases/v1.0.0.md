**Proton Drive Backup 1.0** runs on the official **Proton Drive SDK** (TypeScript, 0.23.0) instead of the Proton Drive CLI. Backups are faster, the container needs a fraction of the memory, and Mirror mode is better protected against deleting the wrong things.

Existing installations upgrade in place. You keep the same compose file and the same `/data`, and you normally don't have to sign in again.

> **The 0.9.x line (CLI-based) is deprecated** and receives no further updates.

## Highlights

### Light on memory
One process does all the work; the CLI started a new process for each operation. In a production install with about 276,000 files (1+ TB), 1.0 uses about **0.7 GB of RAM while uploading**. The 0.9 image needed up to 16 GB on the same data and was killed at 8 GB.

### Fast when little has changed
- A run over **1 million unchanged files takes about 20 seconds** (0.9: almost 3 minutes), and nothing is written to Drive.
- Changed files are read from disk once; the CLI read them twice, and images three times.

### Built for big libraries
- **Folders with more than about 30,000 items:** Proton limits the number of items in one Drive folder. 1.0 continues such a folder in `<folder> · part 2`, `· part 3`, … right next to it. Nothing is skipped, and the app shows which folders were split.
- **No double uploads after a crash or restart:** files that are already on Drive are recognised and kept as they are.
- **Rate limits:** when Proton says "too many requests", the app waits and slows down by itself. Files are never skipped because of it.

### A safer Mirror
- **Offline shares:** an offline NAS share, including one mounted inside a source, never leads to deletions on Drive.
- **Safety limit:** the 30 % limit counts everything inside a removed folder.
- **Identity check:** an item goes to the Drive trash only if it is still the item this backup uploaded, in the same place. Folders that also hold other files are kept.
- **Preview:** shows exactly what the next run would delete, using the same rules as the run itself.

### A friendlier interface
- **Every screen size:** the app works on phones, tablets and desktops.
- **Status first:** your backup sets come first, with progress and the result of the last run.
- **Text size:** adjustable in **Settings → Display**.
- **Long paths:** they stay readable — hover over a path to see it in full.
- **Upload speed limit:** works without `NET_ADMIN`.

## Upgrading

```bash
docker compose pull && docker compose up -d
```

You don't need to back anything up by hand. On its first start, 1.0 keeps a copy of your old database (`backup.db.pre-sdk.bak`) and of your Proton session (`proton/auth-session.pre-sdk.json`) before it changes anything.

- **Pinned tag:** if you pin a tag, switch it to `:1` (all 1.x releases), `:1.0` (bug fixes only) or `:1.0.0`.
- **The first run:** it reads each existing Drive folder once, to pick up the files the old version had already uploaded. A set whose files haven't changed uploads nothing.
- **Rolling back:** pin your previous image (for example `:0.9.0-21`) and start it again. 0.9 can still read the database.
- **All the details:** see the [upgrade and rollback guide](https://github.com/traktuner/docker-proton-drive-backup/blob/main/docs/UPGRADE.md).

## Good to know

Nothing you set up needs to change. A few things behave differently:

- **Hidden files:** switching "Include hidden files" off no longer makes Mirror delete hidden files that are already on Drive. They are left alone, like excluded files.
- **Symbolic links:** they are not followed. Each link is listed in the run result, and Mirror never deletes what a link replaced. To back up a link's target, add the target as a source.
- **Config import** (`/config/backup-sets.yaml`): only the settings that are in the file are changed. Everything else stays as it is.
- **Image tags:** they are plain versions now — `1.0.0`, `1.0`, `1` and `latest`. `latest` only moves with a release. `main` and `<commit>` tags are untested builds.
- **Old CLI settings:** settings that only the CLI used are ignored and can be removed from your compose file:
  - `PROTON_DRIVE_CREDENTIALS_STORE`
  - `PROTON_DRIVE_LOG_LEVEL`
  - `BUN_JSC_forceRAMSize`
  - `PROTON_DRIVE_CLI`
  - `cap_add: [NET_ADMIN]`
