**Proton Drive Backup 1.0** replaces the Proton Drive CLI with the official **Proton Drive SDK** (TypeScript, 0.23.0) inside the app. It is faster, needs far less memory, and is safer in Mirror mode. Your existing installation upgrades in place: same compose file, same `/data`, no new login in the normal case.

> **0.9.x (the CLI-based line) is deprecated.** It gets no further updates. Please move to 1.0.

## Upgrade in 3 steps

1. Stop the container and back up the host folder behind `/data`, or snapshot the dataset.
2. `docker compose pull && docker compose up -d`. If you pin a tag, change it to `:1` (all 1.x), `:1.0` (fixes only) or `:1.0.0` first.
3. Open the web UI. Check that your sets, schedules and history are there and that you are still signed in.
   - The first run of an unchanged set uploads nothing.
   - The first run after the upgrade reads each existing Drive folder once, to pick up files the old version had already uploaded. Later runs skip this.

To roll back, pin the old image (`:0.9.0-21` or your previous tag) and start it again. The database stays readable by 0.9, and the app keeps a copy of your old database and session (`backup.db.pre-sdk.bak`, `proton/auth-session.pre-sdk.json`). The full guide covers every case: [Upgrade and roll back](https://github.com/traktuner/docker-proton-drive-backup/blob/main/docs/UPGRADE.md).

## What is better

- **Much less memory.** One process instead of one CLI process per operation.
  - In a production install with about 276,000 files (1+ TB), the container used about 0.7 GB of RAM while uploading.
  - The 0.9 image needed up to 16 GB there and was killed (out of memory) at 8 GB.
- **Much faster when nothing changed.** An unchanged run over 1 million files takes about 20 s instead of almost 3 minutes. It writes nothing to Drive.
- **Every changed file is read once.** The CLI read each file twice, and images three times.
- **Very large folders work.** Proton allows about 30,000 items per Drive folder. When a folder is bigger, the rest continues in `<folder> · part 2`, `· part 3`, … next to it. Nothing is skipped, and the app shows which folders were split.
- **No duplicate uploads after a crash.** The app checks what is already on Drive and adopts it instead of uploading it again.
- **Rate limits are handled.** When Proton answers "too many requests", the app waits and slows down by itself. It never skips files because of it.
- **The speed limit works without `NET_ADMIN`.** You can remove `cap_add: [NET_ADMIN]` from your compose file.
- **The app adapts to the screen** (phone, tablet and desktop) and has a **text size setting**: Settings → Display.

## Mirror mode is safer

- A missing or offline NAS share is detected, and nothing is deleted on Drive.
- The 30 % safety limit now counts everything inside a removed folder. A vanished share or a moved top folder is caught.
- Before an item goes to the Drive trash, the app checks that it is still the item this backup uploaded, in the same place. Folders with content from somewhere else are kept.
- **Preview** shows exactly what a run would delete, using the same rules as the real run.

## Changes you should know about

- **Hidden files:** if you switch "Include hidden files" off, Mirror now leaves hidden files that are already on Drive alone. It no longer deletes them, just like excluded files.
- **Symbolic links** are not followed. Each one is listed in the run result. A link never causes the folder it replaced to be deleted on Drive. To back up the target of a link, add the target as a source.
- **Config re-import** (`/config/backup-sets.yaml`) only changes the settings the file contains. Settings left out of the file keep their current value.
- **Image tags** are now plain versions: `1.0.0`, `1.0`, `1`, `latest`. `latest` moves only with a release. `main` and `<commit>` tags are untested builds.
- **Settings only the CLI needed** are ignored if they stay in your compose file: `PROTON_DRIVE_CREDENTIALS_STORE`, `PROTON_DRIVE_LOG_LEVEL`, `BUN_JSC_forceRAMSize`, `PROTON_DRIVE_CLI`.

## Notes

- **Platforms:** `linux/amd64` (tested) and `linux/arm64`.
- **How the app identifies itself to Proton:** as a third-party app (`external-drive-proton_drive_backup@1.0.0`). It is an independent community project, not made or supported by Proton AG.
