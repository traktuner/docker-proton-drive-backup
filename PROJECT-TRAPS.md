# Project traps

- Do not enable source editing through the generic PATCH: it can clear the catalog, so the next no-exclude Backup/Mirror can use `-f skip` and record a changed retained file without uploading its new revision; add roots only through the additive endpoint, preserve catalog rows, reject queued or running sets, and keep removal forbidden (`src/app/api/backup-sets/[id]/source-paths/route.ts`, `src/app/api/backup-sets/[id]/route.ts`, `src/server/engine.ts`).
- Do not place application routes or source files in a directory named `sources`: the root `.gitignore` rule `sources` hides that directory at any depth, so Git can silently omit a complete API route (`.gitignore`, `src/app/api/backup-sets/[id]/source-paths/route.ts`).
- Do not repair or reify this checkout's dependency tree directly on the SMB share with npm 11.19: three runs ended with `ENOENT` while npm tried to `chmod` `node_modules/baseline-browser-mapping/dist/cli.cjs`, including after recursive permission repair and a successful create/chmod/rename/delete probe in that exact directory; use a lockfile-based local work copy for dependency installation and verification (`package-lock.json`, `node_modules/baseline-browser-mapping/dist`).
- Never import `@protontech/*` or `src/server/proton/runtime.ts` from Next.js code. Next can instantiate route modules more than once per process, and `@protontech/crypto` keeps a process-wide CryptoProxy singleton; the SDK is bundled once by `scripts/build-proton.mjs` into `dist-proton/runtime.mjs` and loaded through `runtime()` in `src/server/drive.ts` (`webpackIgnore` import). Route code uses only `src/server/proton/types.ts` (`src/server/drive.ts`, `next.config.mjs`).
- `/data/proton/auth-session.json` in the CLI's exact format is the upgrade AND rollback contract: refresh tokens are single-use, so the SDK release must keep writing the current tokens to that file (atomic rename, unknown fields such as `cachePassword` preserved) — a separate store would log out every rollback (`src/server/proton/session-store.ts`, `test/upgrade/upgrade.sh`).
- `@protontech/crypto` imports `openpgp/lightweight`, which `@protontech/openpgp` exports only for browsers; without the esbuild alias the bundle fails at load with `ERR_PACKAGE_PATH_NOT_EXPORTED` (`scripts/build-proton.mjs`, `src/server/proton/PATCHES.md`, `test/proton-runtime.test.ts`).
- npm 11.20+ (the npm in `node:26` images) skips dependency install scripts unless `package.json` `allowScripts` approves them. That silently breaks native addons such as better-sqlite3 (the reason SQLite moved to the built-in `node:sqlite`); do not add dependencies that need an install script (`package.json`).
- A `DriveError` has a `.code` ('RATE_LIMITED', 'NOT_FOUND', …) just like a Node fs error; check `driveErrorCode(e)` first and treat `.code` as an errno only when it is not a DriveError, or transient Drive errors are misread as file errors and not retried (`src/server/engine.ts`).
- The Mirror removal diff relies on the scanner's order: a folder event (with its subfolder names) is followed by that folder's files before any subfolder is entered. Keep that order in `SCAN_WORKER` (`src/server/local.ts`, `RemovedCollector` in `src/server/engine.ts`).
- `account.origin` decides whether a session counts as taken over from a 0.x install (auto-bound) or needs a confirmation: only `upgrade.fromCli` + an existing session file at the first start of 1.x is a takeover; any login started in 1.x or a takeover session Proton rejects resets it to `login` (`src/server/drive.ts`).
- Do not "parallelise" SDK decryption with @protontech/crypto's worker pool on worker_threads: the pool imports every key into EVERY worker, and listing a Drive folder unlocks one node key per item, so measured key-unlock throughput DROPS with workers (in-process 456/s, 1 worker 303/s, 4 workers 127/s; message decrypts rose only 755→981/s). The real lever is not listing at all: each existing Drive folder is listed once, ever, with chunked adoption (`listed_dirs`, `RunContext.ensureListed` in `src/server/engine.ts`).
- Never hand the SDK a long-lived AbortSignal (the run's): `FileUploader` adds an `'abort'` listener to the signal it gets and never removes it, so every finished uploader and its buffers stay reachable as long as that signal lives (production: live heap +4.4 MB/min during uploads). Give each upload its own `scopedSignal(runSignal)` and `dispose()` it when the upload ends (`src/server/proton/runtime.ts` `runUpload`, `test/proton-runtime.test.ts`).
- Every name lookup inside a folder must go through `RunContext.lookup()`, which honours `listed_dirs`; calling `findIn`/`childMap` directly re-lists the whole Drive folder (a 36k-item folder costs ~10 min of CPU). The exceptions are deliberate: mirror deletes, part rediscovery in `overflow`, and verify (`src/server/engine.ts`).
