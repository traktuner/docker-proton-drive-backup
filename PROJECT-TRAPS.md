# Project traps

- CLI 0.8.0 requires `-f create-new-revision` for changed files; `-f merge` was valid only in older CLI versions and makes Backup/Mirror uploads fail, while folder conflicts still use `-d merge` (`src/server/engine.ts`, `src/server/cli.ts`, `Dockerfile`).
- Do not enable source editing through the generic PATCH: it can clear the catalog, so the next no-exclude Backup/Mirror can use `-f skip` and record a changed retained file without uploading its new revision; add roots only through the additive endpoint, preserve catalog rows, reject queued or running sets, and keep removal forbidden (`src/app/api/backup-sets/[id]/source-paths/route.ts`, `src/app/api/backup-sets/[id]/route.ts`, `src/server/engine.ts`).
- Do not place application routes or source files in a directory named `sources`: the root `.gitignore` rule `sources` hides that directory at any depth, so Git can silently omit a complete API route (`.gitignore`, `src/app/api/backup-sets/[id]/source-paths/route.ts`).
- Do not repair or reify this checkout's dependency tree directly on the SMB share with npm 11.19: three runs ended with `ENOENT` while npm tried to `chmod` `node_modules/baseline-browser-mapping/dist/cli.cjs`, including after recursive permission repair and a successful create/chmod/rename/delete probe in that exact directory; use a lockfile-based local work copy for dependency installation and verification (`package-lock.json`, `node_modules/baseline-browser-mapping/dist`).
